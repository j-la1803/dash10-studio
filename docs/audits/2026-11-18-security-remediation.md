# Dependency security triage and mobile performance follow-up

Scope: Dash 10 Studio, production baseline `bc5f103`; November 18, 2026 (Chicago). No exploits, destructive requests, user deletion, schema push or CMS content writes were performed. Findings are reachability assessments, not proof of compromise or absence of compromise.

## Security decision

All 10 critical and 36 high records were reviewed against primary GitHub advisory descriptions and the configured deployment. Full installed versions, vulnerable/patched ranges and **every dependency path** are in [the accompanying JSON](2026-11-18-security-advisories.json); repeated peer paths do not represent separate installed exploits.

The highest-priority remaining risks are Payload Postgres query SQL injection and Form Builder RCE: the deployed app has the relevant public query/submission surfaces. Restricting collection access or the custom inquiry hook is not a complete remediation. Payload multipart parsing DoS is also publicly reachable. Avoid declaring the deployment secure while these remain open.

Candidate changes: Next 16.2.6 → 16.4.5 and matching eslint-config-next, semver-compatible transitive refreshes, pinned Undici 7.29.0 → 7.30.1 and source-map-js 1.2.1 → 1.2.2 overrides. Next's own optional image processor resolves Sharp >=0.35.5. Direct Payload Sharp remains 0.34.2 pending approval. No audit fix --force, major framework upgrade, secret or infrastructure change.

Payload must be upgraded coherently to 3.90.0 across all packages. The maintainer release explicitly requires a relational migration (including password-reset schema changes) and changes auth/upload/form behavior; rich-text Lexical changes from 0.41 to 0.50. Built-in features require no content migration, but compatibility and schema review are mandatory. Sharp 0.35 drops Node 18, removes deprecated API fields and changes image defaults; this is a breaking pre-1.0 minor. These changes are held for explicit approval before implementation. Review generated SQL against an isolated schema, confirm purely additive changes and backup/restore readiness, test authenticated editors/preview/save plus existing posts, then apply only inspected migration through the established process. Never use development schema push on the shared CMS.

Happy DOM is a server-capable Lexical transitive dependency, not automatically a test-only issue. Its RCE requires evaluation of attacker JS; no such app route/configuration was found. Its HTML-resource SSRF prerequisite also was not found in public request handling. The patched major must be evaluated with upstream Lexical/Payload, not forced globally. CSS/PostCSS/source-map and YAML schema tooling are build-time here despite appearing in the production dependency tree. No runtime untrusted CSS/YAML processing endpoint was found.

## Mobile LCP diagnosis and changes

The actual measured LCP node is `video.dash-hero-video`; its LCP resource URL is the mountain **poster**, not the MP4. Do not equate that selector with proof that video decoding is the LCP resource. A fresh pre-change Lighthouse 13.6.0 production sample, default simulated mobile throttling, reports LCP 6.055s / Performance 77. The previous audit sample was 5.705s / 79. Observed unthrottled insight timings and Lighthouse's simulated LCP are different measurements and must not be mixed.

The poster is already high-priority, discoverable in server HTML, ~85KB. Initial requests additionally load ~258KB of full fonts and roughly 300KB of JavaScript, plus decorative video ranges before initial resource loading completes. Render-blocking CSS is ~19KB transferred. The report identifies ~95KB unused initial JS (estimated ~450ms simulated LCP opportunity in the local sample); removing framework/admin dependencies from the initial route needs a separate compatibility review. No Google/HubSpot requests occur before consent, so third-party scripts do not explain the clean first-visit baseline. Consented tracking behavior remains covered by regression tests.

Changes reuse the existing hero and approved fonts:

- Latin/punctuation/technical-symbol WOFF2 subsets, ~100KB combined instead of ~258KB. Every retained outline is checked against the approved font. Original full WOFF2 faces remain available through complementary unicode ranges, preserving other scripts and avoiding needless downloads for glyphs the original font never contained.
- Decorative MP4 source is attached after window load and two animation frames, allowing the poster and initial resources to paint before video transfer. No video samples are re-encoded; framing, overlays, once-only playback, rate, pause control and final-frame hold stay intact. Reduced-motion visitors do not request the MP4. Server-rendered content and poster remain visible without JavaScript.
- New browser regressions hold the priority font request and verify no early video transfer, then verify playback initialization after release; reduced-motion checks verify no MP4 request. Existing end-hold/rate and design tests remain.

The candidate's intermediate local Lighthouse measurement improved from 4.885s / 82 (an avoidable fallback font still loaded) to 4.286s / 86 after character coverage was corrected; this is diagnostic, **not** a production before/after comparison. Final production results are recorded after deployment below. No claim of a 2.5s pass or field CWV pass is made without that evidence.

## Verification and release gate

Production build and TypeScript pass. Offline unit suite: 16 pass, shared-CMS read test skipped by default. Lint: zero errors, three unchanged template warnings. Focused Chrome suite: 35 pass, covering 1440/1280/mobile layout, normal-flow stories/sticky rail, video/end hold, marquee, FAQ, consent/single GTM/blocked tracking, published articles/private APIs, sitemap and metadata. No inquiries were submitted, admin test accounts created, CMS records changed or migrations applied.

Only verified compatible changes may ship through main → existing Vercel project/domain. Payload/Sharp breaking changes remain gated by owner approval. Their open production risks are **not resolved by this release**.
